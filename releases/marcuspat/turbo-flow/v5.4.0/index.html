v5.4.0 — gate fairness + npm

Oct 31, 2026 · Shell

Gate fairness

  • Verdicts are pinned to the head they gated — every verdict comment carries gated-head: and a commit status on that exact SHA. New commits leave the PR ungated again, and --sweep re-gates it instead of trusting a stale approval.
  • PRE-EXISTING rule — reviewers can only block for defects this diff introduces; identical-on-base is a non-blocking note.
  • Rounds are capped (GATE_ROUND_CAP, default 3). Past the cap the gate exits 4 and the continue / park / restructure fork belongs to a human, not another auto-round (GATE_FORCE=1 overrides consciously).
  • Round memory — from round 2 the reviewer receives the prior round's findings as scrubbed data, so addressed items stop coming back.

npm

The kit now ships as turbo-flow on npm:

npx turbo-flow@5.4.0 help
npm i -g turbo-flow@5.4.0

Same kit, same subcommands as tf, pinned per release. The bin shim is symlink-safe (npx and global installs invoke through symlinks) and fails closed if the payload is missing. The self-test suite is green from inside the published package, not just the repo.
